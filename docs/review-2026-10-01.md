# Review and Windows delivery — 1 October 2026

This review focused on data preservation, checkout correctness, actual build failures, and installation on a PC without developer tools. The supplied folder has no Git history, so changes were made directly in the extracted project.

## Corrections

- Weight quantities below 1 were clamped to 1 by both the cart store and editor. Both now accept 0.001; database quantities for inventory, transaction lines, purchasing, and expiration batches preserve three decimals through a migration.
- Backup exports omitted secondary barcode rules, personal purchases, weight metadata, debt details, and manual-pricing flags. Version 2 exports and restores these fields; version 1 remains readable. PostgreSQL exports use a consistent transaction snapshot. Restore deletes dependent rows first and can audit restores from another store without referencing a removed account.
- Restore now asks before replacing data, clears stale carts/cache, and requires signing in with the restored accounts.
- Debt settlement treated the USD and LBP display balances as two payments. Automatic settlement uses one currency; explicit mixed payments reduce the outstanding amount before applying the second currency. The UI no longer pre-fills both equivalent balances or repeatedly settles an already-settled card.
- Editing a purchase added the same line twice to the response collection through EF relationship fix-up. Removed the redundant addition.
- Receipt generation now precedes committing checkout, preventing a PDF failure from leaving a recorded sale behind a failed checkout response.
- Updated React Query v5 usage so successful store-profile and exchange-rate fetches actually update the UI.
- Corrected compiler errors involving scanner globals, Vite types, button variants, nullable values, and persisted cart types. Production builds now include type checking.
- Preserved custom request headers and displayed server `message` errors correctly. Failed login promises are handled, and logout clears cached queries.
- Removed the unauthenticated `/seed` route, restricted CORS to configured origins, removed the checked-in production signing key, and required a 256-bit-or-longer signing key. Development/testing have a clearly scoped fallback.
- New packaged stores create only the owner's admin account and no demo products or shared default credentials. Local database/JWT credentials are random and encrypted through Windows.
- The packaged app now includes and starts its backend/database, waits for readiness, prevents duplicate app instances, and stops its services on exit. Fixed a Windows inherited-pipe issue discovered during integration testing.
- Disabled placeholder update requests; restricted desktop navigation/new windows and serial permission grants to the app window.
- Removed the hard-coded COM4 default and corrected low-contrast toolbar buttons found during packaged-app visual checks.
- Disabled optional ML requests in the standalone desktop runtime, including the anomaly call made during ordinary barcode scans; scanning does not require the Docker ML service.

## Test repairs

The pre-existing backend test project did not compile. Fixed missing imports, logger constructor arguments, and an xUnit API mismatch. Its API factories also selected a new in-memory database per scope, so test requests did not share seeded data. They now use one database per test with isolated hosts.

Several old assertions were inconsistent with the application model: one inventory row per product, money tendered in distinct currencies, settled transactions excluded from outstanding debts, and the indexed validation key for a duplicate barcode. Corrected these fixtures/assertions without disabling tests. A currency test expected change even though its input underpaid by 300 LBP; it now explicitly tests that rounding case.

## Release limits and follow-up

Verified locally: all 55 backend tests pass; frontend type checking and lint pass; cart regression tests pass; fresh-store tests run against the packaged PostgreSQL/backend, including barcode scans without ML, 0.001 quantities, PDF checkout, debt settlement, backup restore, restart persistence, and API access controls. Packaged Electron setup, login, reopening, scanner-idle state, and screenshots were also checked. Test artifacts are in `artifacts/` and local logs in `.tools/`.

- This is an unsigned Windows x64 build. Code signing, an update feed, and clean-machine acceptance on a separate PC remain release operations.
- Printer/scanner hardware and the optional ML service require separate device/service testing.
- No cloud sync or phone access is enabled. The desktop API/database bind to loopback.
- Multi-terminal concurrent stock updates, request idempotency, stronger login/session controls, automated off-PC backups, and dependency lifecycle upgrades deserve a subsequent production-hardening pass. This review is not a complete security audit.
- Installer updates preserve the data folder, but a backup and restore drill remain necessary before replacing a live-store version. Database major-version upgrades need a dedicated migration process.
